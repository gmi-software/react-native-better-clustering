Migrating from react-native-clusterer

react-native-clusterer and this package both run supercluster in C++ over Nitro, and their hooks take the same arguments. The difference is where the work runs: react-native-clusterer builds its index on the JS thread, and its useClusterer rebuilds it on every render. Here the index builds on a background thread, once per change of the points. This page compares react-native-clusterer 5.0.2.

Both libraries need the New Architecture and react-native-nitro-modules. This package also needs React Native 0.78+ and declares react-native-maps as a peer dependency, though /hooks, /engine and /geojson don't import it. See Platform Setup.

Before and after​

- import { isClusterFeature, useClusterer } from 'react-native-clusterer'
+ import { isClusterFeature } from 'react-native-better-clustering/geojson'
+ import { useClusterer } from 'react-native-better-clustering/hooks'
  import MapView, { Marker } from 'react-native-maps'

  const MAP_DIMENSIONS = { width: MAP_WIDTH, height: MAP_HEIGHT }
+ // react-native-clusterer's defaults; this package defaults to 1 and 20.
+ const OPTIONS = { minZoom: 0, maxZoom: 16 }

  function Map({ markers }) {
    const mapRef = useRef(null)
    const [region, setRegion] = useState(initialRegion)
-   const [points] = useClusterer(markers, MAP_DIMENSIONS, region)
+   const [points] = useClusterer(markers, MAP_DIMENSIONS, region, OPTIONS)

    return (
      <MapView
        ref={mapRef}
        initialRegion={initialRegion}
        onRegionChangeComplete={setRegion}
        style={MAP_DIMENSIONS}
      >
        {points.map((point) => (
          <Marker
            key={
              isClusterFeature(point)
                ? `cluster-${point.properties.cluster_id}`
                : `point-${point.properties.id}`
            }
            coordinate={{
              latitude: point.geometry.coordinates[1],
              longitude: point.geometry.coordinates[0],
            }}
            onPress={() =>
              isClusterFeature(point) &&
              mapRef.current?.animateToRegion(point.properties.getExpansionRegion())
            }
          />
        ))}
      </MapView>
    )
  }

markers is the same array of GeoJSON point features as before, and the key above needs a unique properties.id on each. Keep it in useMemo or state: a new array with the same coordinates in the same order, and the same clusterProperties values if you use them, no longer rebuilds the index, but the hook still compares every point with the previous array. When only other properties change, a point on screen keeps its previous feature object, old properties included, until the region changes, where react-native-clusterer returns new objects on every query. Read a property that changes from markers by properties.id.

Clusterer takes the same props (data, region, mapDimensions, options, renderItem), plus onError.

Which clusters you get​

With the same options, the two libraries choose the same zoom for a region and query the same area. In the hook benchmark they returned the same number of features at every step, at 10,000 to 100,000 points.

  • Zoom range. minZoom is 1 and maxZoom is 20 here, where react-native-clusterer uses supercluster's 0 and 16. Pass both, as above, to keep your clusters.
  • Zoom selection. useClusterer and Supercluster pick the zoom for a region the way react-native-clusterer does: with geo-viewport's method and a tile size equal to extent (512). viewportTileSize changes the tile size; see Zoom selection.
  • radius is used as given. react-native-clusterer truncates it to an integer, so a fractional radius clusters slightly differently.
  • Above maxZoom, both return every point on its own (see Above maxZoom).
  • generateId is not an option here; supercluster only uses it for getTile.

Aggregating properties​

react-native-clusterer supports neither supercluster's map and reduce nor another way to aggregate: its options parser reads only radius, minZoom, maxZoom, extent, minPoints and generateId. Here, clusterProperties sums, or takes the minimum or maximum of, numeric point properties into each cluster, in C++ while the index builds:

const [points] = useClusterer(markers, MAP_DIMENSIONS, region, {
  clusterProperties: [
    { source: 'price', key: 'totalPrice', reduce: 'sum' },
    { source: 'rating', key: 'bestRating', reduce: 'max' },
  ],
})
// A cluster's properties.totalPrice and properties.bestRating

source can be a dot path (details.price); key defaults to its last segment. See SuperclusterOptions.

What runs on which thread​

Stepreact-native-clusterer 5.0.2This package
Reading the pointsJS thread: native code reads each feature's coordinates through JSIJS thread: the points are checked and packed into one buffer, copied to native in one call
Building the indexJS thread, in the same synchronous callA background thread
When it rebuildsOn every render of the component that calls the hook, and again when data or an option changesOnly when the points' coordinates, their order or a clusterProperties value changes, or an option changes
Clusters for a regionJS thread, a synchronous native call, in an effect after the renderJS thread, a synchronous native call, during the render
Clusters on the first renderYes: the index is built during that renderNo: [] until the first build has loaded
Freeing the indexWhen the garbage collector finalizes itdestroy(), which the hook calls on unmount and after replacing an index

The rebuild on every render comes from how useClusterer creates its index in react-native-clusterer 5.0.2:

const [supercluster, setSupercluster] = useState(
  new SuperclusterClass(options).load(data)
)

useState keeps only the first value, but the argument is evaluated on every render: each render builds a full index and throws it away. A pan builds two, since the region change renders once and the new clusters render again. The index for a new data array is built in an effect, so it blocks the JS thread too.

The other side: react-native-clusterer has clusters on the first render, and here the hook returns [] until the first build loads, then keeps the previous clusters while a new build runs. Show a placeholder if a blank first frame matters, and use supercluster.isLoaded before calling query methods yourself.

Other differences​

  • Point features. Queries return your input feature objects for points. react-native-clusterer creates new ones on every query, with your properties object inside.
  • getExpansionRegion() fits every point of the cluster, from its bounds, with the same 1.5× margin. react-native-clusterer fits the cluster's children at the first zoom where it splits.
  • getTile has no equivalent.
  • Errors. A failed build is thrown during render, or passed to onError (see Hooks).
  • More methods. Supercluster adds loadAsync, getClusterBounds, getAllLeaves and destroy (see Headless engine).
