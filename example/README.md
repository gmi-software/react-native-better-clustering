# Example app

An Expo app with a menu of scenarios that exercise real-world usage of `react-native-better-clustering`. A dev HUD on each one shows JS FPS, mounted markers, marker mounts and engine builds, and the datasets are seeded, so every run sees the same markers.

| Scenario | What it exercises |
| --- | --- |
| Basic | 2,000 static markers across Poland |
| Parent state | A selection and a visible list from `onMarkersChange={setState}` with inline children, plus a 2 Hz parent re-render |
| Live data | Appending and removing markers, on demand or one per second |
| Live fleet | 1k to 50k static markers and 20 vehicles moving 1 to 10 times a second, with how far the index lags behind, clustered or with `cluster={false}` |
| Co-located markers | Spiderfy from zoom 19 or on press; 1,000 markers at one spot stay a bubble |
| Antimeridian | Markers on both sides of ±180° |
| 10k / 50k markers | Large datasets, with the time to first markers |
| Custom `renderCluster` | Clusters drawn by the app |
| `clusteringEnabled` toggle | Clustering turned off and on with the map mounted |
| Benchmark | The [device benchmark](./bench) against react-native-map-clustering |

## Running it

```bash
cd example
bun install
npx expo prebuild --clean
bun run ios   # or: bun run android
```

`ios/` and `android/` are generated by `expo prebuild` and git-ignored. The Maestro end-to-end flows (`bun run e2e`) and the machine setup they need are in [CONTRIBUTING.md](../CONTRIBUTING.md).
